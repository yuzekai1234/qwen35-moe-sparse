## 多 agent 协调

1. 每次先读 README、共享 `BOARD.md` 和 `launch.sh status`；确认任务是否已完成或被认领。
2. 每个 agent 使用自己的 owner 名，配置变更使用新的 run-id；不要修改他人的运行配置或历史结果。
3. 通过 `launch.sh train/eval` 认领并加锁。显卡必须无计算进程且空闲；不要因“剩余显存还够”就和他人的训练叠跑。
4. 锁只能协调遵守本入口的 agent；同时检查 nvidia-smi。未经团队约定不能抢占其他作业。
5. 长作业用 tmux；交接写明 run-id、owner、GPU、命令、日志、断点及状态。完整训练、完整评测、完成提交分别报告。
6. 遇到任务记录过期，先核实 PID/子进程/GPU。自己的已退出任务可显式 --resume；他人的登记先协调，不删除来抢任务。
7. 小规模、切片、受干扰计时及估计值必须注明。四档同一评测配置齐全后才运行 score.py 比较总分。
8. 不把 C1 的记忆或校准系数冒充 C4 自己的产物。混合预测需要针对各候选构建自己的记忆与校准，并验证因果性。

## 版本与结果

准备阶段冻结源代码和配置哈希；训练开始后更改代码必须另开 run-id。保存失败日志。
本次四档是起始配置，尚未证明 GPU 适配、最优尺寸或最终收益。跑出数据后可以搜索更好的尺寸、专家数、学习率、上下文和推理实现。
更新仓库用独立分支/工作树，避免覆盖其他人的未提交改动。更新共享 BOARD.md 和状态；不复制凭据、权重、数据、虚拟环境进 Git。

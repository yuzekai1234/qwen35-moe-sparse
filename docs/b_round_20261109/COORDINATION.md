# 同学与agent协作约定

用户已授权通过新服务器文档直接协调。每次开始工作先读README、实时任务状态和最新交接；结束前写入结果、证据路径、待处理问题及下一步。收到对方问题后，在自己的新交接文件中引用问题编号回复，不依赖用户转述。

## 当前分工

| 事项 | 当前归属 | 协作方式 |
|---|---|---|
| 新机C3/C2训练及顺序评测 | codex-gzy，已有自动队列 | 同学可检查；需调整时先在交接中写明原因和目标，核验队列再执行 |
| 原gpu1上的改版C4 | 已由另一位同学运行 | 请负责同学登记owner、run-id、源码版本、最终权重和评测路径 |
| 架构与Model Card正文 | codex-gzy已提供初稿，共同修改 | 明确正在修改的文件/小节，修改后提交Git并写摘要 |
| 消融与逐样本分析 | 待同学认领 | 先写对照、预算、样本划分和输出路径，再用独立run-id运行 |
| 四档结果汇总与提交冻结 | 待结果齐全后认领 | 对齐家族、精度和评测设置，保留权重哈希与完整回执 |

表中“待认领”不代表对方已经接受任务。认领人在交接文件中填写自己的owner和具体范围。

## 交接格式

在 `handoffs/` 新建 `YYYYMMDD-HHMM-owner.md`，时间使用Asia/Shanghai。每人维护自己的文件；不要覆盖或删除对方记录。至少包括：

```text
时间 / owner / 所处理的问题编号
已认领范围及预计修改文件
已完成事项
源码提交 / run-id / 配置哈希
结果与证据路径（注明完整或部分、实测或估计）
等待对方确认的问题
下一步与停止条件
```

另一方通过新文件回复“确认/有异议/已处理”，并引用原文件和问题编号。新结论生效后更新主文档，交接历史保留。不要把尚未回复的建议记成双方已同意。

## 文件与实验

- 当前配置主线是E512/top4、三处K2048 LongConv、Engram、loss-free、DWA。结构以实际config和源码为准，旧E1024结果不能冒充当前家族。
- 长卷积的实际位置为Attention/GDN之后、MoE/FFN之前。Model Card修改要与前向实现一致。
- 训练中的 `runs/<run-id>/source`、配置、权重和原始结果保持冻结。新实验使用新run-id；不直接修改现有长训，也不因文档中的旧空闲快照占卡。
- 每次编辑前运行 `git status`，保留他人的未提交修改。范围冲突时使用独立分支或worktree；不reset、clean或强推。只提交自己的文件或修改块。
- 架构讨论主文档后的Model Card正文与独立Model Card文件保持一致。最终权重、实际训练量及成绩由真实运行产物补齐。
- 提升样本集是探索性材料；报告全体/独立验证集和退化样本，不能把按提升筛选的集合包装成整体收益。
- 凭据、私钥和VPN密码不进入文档或Git。
